## 2. 작업 흐름 (한 편)

```
주제 선택 (02 4장 사장님 달력, 독자 질문 1개)
 → 글 유형 고르기 + 이유 1줄 (02 3장)
 → 경험 은행 검색 (없으면 안내형으로)
 → 사실 검증표 만들기 (fact_checks/, 주장마다 원문 확인)
 → 초안 작성
 → check_draft.py (필수 통과, 권고는 고치거나 예외 이유)
 → 독립 심사 (5장, 초안 안 쓴 에이전트)
 → 수정 → 사실 검증표 '확인 완료' 또는 문장 삭제·범위 축소
 → check_draft.py --publish (필수 통과)
 → 사람 확인 6항목 + 승인
 → 네이버 임시저장 (Uplika, draftOnly) → 사람이 "발행"하면 발행
 → 06_publish_log 발행 표 → 7일·30일 성과 표 (7장)
```

## 3. 사실 검증 절차

1. 초안을 쓰기 전에 `fact_checks/<주제>.md`를 `_template.md`로 만든다.
2. 법률·제도·비용·시행일·서비스 기능·보험·통계·판결 주장은 한 줄씩 적는다.
3. **원문을 직접 열어 본 것만** '확인 완료'로 적고 확인일을 쓴다. 검색 요약, 블로그 해설, AI 기억은 원문이 아니다.
4. 원문을 못 찾으면: 문장 범위를 좁히거나, 숫자를 빼고 "관할 기관 확인"으로 바꾸거나, 문장을 지운다.
5. 출처끼리 다르면 '출처 충돌'로 두고 고르지 않는다. 법령 원문을 찾을 때까지 발행 보류.
6. 약관·판결을 AI가 일반 지식으로 추정해 쓰지 않는다.
7. 발행 본문의 "기준일·출처"에는 '확인 완료' 출처만 쓴다. 검증표 자체는 본문에 넣지 않는다.
8. `check_draft.py --publish`가 '미확인'·'출처 충돌'을 막는다. 표에 '확인 완료'라고 적혀 있는 것과 실제로 원문을 봤는지는 사람이 확인한다.

## 4. 경험과 가상 상황

- 경험은 `13_experience_bank.md`에만 있고 사람이 쓴다.
- 실험형·사례형은 경험 은행의 실제 줄(공개 동의 "예")이 있을 때만 쓴다.
- 경험이 없으면 공식 자료로 쓰는 안내형으로 쓴다. 안내형에 `[경험]` 칸을 억지로 만들지 않는다.
- 가상 사례는 `> 가상 시나리오: 예`, 발행 모드에서 자동 실패.
- `[경험]` 빈칸을 지웠다고 경험이 생긴 것이 아니다. 사람 확인 항목이다.

### 5-3. 심사자 규칙

- 초안을 쓴 에이전트는 자기 점검만 한다. 독립 심사를 대신하지 않는다.
- 심사자는 작성자의 점수·결론을 받지 않고 원문과 이 기준만 받는다.
- 점수가 높아도 6번에 중대 오류가 있으면 발행 불가.
- 기준이 그 유형에 맞지 않으면 점수 대신 "기준 부적합: 이유"를 적는다.
- 결과에는 문제 위치(줄), 고칠 이유, 우선순위(높음·중간·낮음)를 적는다.
- 심사 결과 파일 머리에 편향 고지를 단다: "평가 항목 일부는 우리 지침에서 나왔다. AI 심사이며 실제 독자 반응이 아니다."

## 6. 벤치마킹 방법 (다음 조사부터)

### 6-1. 네 집단을 나눈다

1. 같은·비슷한 검색어 상위 노출 글
2. 소상공인 온라인 운영·홍보 전문 블로그
3. 공감·댓글 등 반응이 확인되는 글
4. 우리 블로그 발행 글

다음 조사 목표: 같은 분야 블로그 약 10곳 × 3~5편 = 30~50편. **통계적 대표성이 있는 표본이라고 쓰지 않는다.**

### 6-2. 글마다 기록할 것

조사일 · 블로그·글 주소 · 검색어와 검색 의도 · 노출 위치와 확인 조건(기기, 로그인 여부, 시각) · 제목·도입 구조 · 소제목 순서 · 표·도식·이미지의 역할 · 경험·근거 쓰는 방식 · 독자가 실행할 수 있는 정보 · 확인된 공감·댓글 · **확인 못 한 항목**

- 조회수·체류시간 등 비공개 데이터는 추정하지 않는다.
- 노출 위치는 개인화·시점·환경에 따라 다르다고 적는다.
- 상위권이라는 사실과 본문 품질은 따로 판단한다.
- 문장·독창적 표현은 베끼지 않는다. 직접 인용은 15자 이내 최소한 (CLAUDE.md 네이버 접근 규칙).
- 각 발견에 등급을 붙인다: [관찰] 실제 본문에서 본 것 / [반복] 여러 글에서 반복 / [가설] 성과에 도움이 될 것이라는 추정 / [검증] 우리 발행 데이터로 확인.

### 6-3. 파일

새 조사는 `benchmark/YYYY-MM-DD_<검색어>.md`에 쌓는다 (폴더는 첫 조사 때 만든다). 기존 `11_sim_vs_toptier.md`, `12_evaluation.md`는 이전 기록으로 보존하고 고치지 않는다.

## 7. 성과 학습 루프

1. 발행 7일·30일 뒤 `06_publish_log.md` 성과 표를 채운다. 측정 못 한 지표는 "측정 불가".
2. 잘된 글의 특징은 **[가설]**로 적는다. 조회수가 높다고 그 글의 모든 기법이 성공한 것으로 보지 않는다 (주제·시점·노출 조건을 함께 적는다).
3. 비슷한 검색 의도의 다음 글에 그 기법을 적용하고 결과를 비교한다.
4. 반복된 특징과 예외를 모두 적는다.
5. **한 편만 보고 지침을 바꾸지 않는다.** 같은 방향의 관찰이 여러 편에서 쌓였을 때 `02` 변경 기록에 근거를 달아 바꾸고 사용자 승인을 받는다.
6. 발행 글이 충분히 쌓이기 전에는 성과 기반 규칙을 자동화하지 않는다.
