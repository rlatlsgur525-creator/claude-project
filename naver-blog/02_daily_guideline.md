## 0-1. 규칙 등급 (v1.6)

판정은 `tools/check_draft.py`가 등급별로 출력한다. 스크립트가 판정할 수 없는 항목은 "사람 확인"으로 남고, 자동 통과로 치지 않는다.

### A. 필수 (하나라도 실패하면 발행 보류)

| 항목 | 판정 |
|---|---|
| 실제 경험을 AI가 지어내지 않음. 지어낸 사례는 `> 가상 시나리오: 예` 표시 | 스크립트(발행 모드) + 사람 |
| 빈칸 `[경험]`·`[숫자]`, 이미지 자리표시 0 | 스크립트(발행 모드) |
| 중요한 법·제도·숫자 주장이 사실 검증표(`fact_checks/`)에서 '확인 완료' | 스크립트(발행 모드, 표 상태) + 사람(원문을 실제로 봤는지) |
| 계산 예시·도식 숫자가 본문과 일치 | 사람 |
| 제목이 약속한 질문에 본문이 답함 | 사람 |
| 독자가 오해할 중대한 논리 모순 없음 | 사람 |
| 개인정보·저작권·이미지 사용 권한 문제 없음 | 사람 |
| 보험·금융 주제 준법 확인 (상품 권유·단정 표현 없음), 사람 승인 | 사람 |
| 메타데이터: 제목 줄, 메인 검색어 머리말, 메인 검색어가 제목이나 본문에 있음 | 스크립트 |

### B. 권고 (대부분의 정보성 글에 유리. 유형에 따라 벗어날 수 있음)

| 항목 | v1.5 기준값 (권고로 유지) |
|---|---|
| 답을 초반에 준다 | 2줄째 굵은 답, 7줄 안 범위 예고 |

## 1. 고정 뼈대 (매편 같아도 되는 부분)

토론 5명 만장일치 + 공감 상위 글(끌림 공감 107 / 72 / 55 / 34) 흐름과 같은 구조다.

```
[첫 화면]  1줄: 꼴 회전 (2장)
           2줄: 굵은 답                      ← 고정
           3~6줄: 이유 + 가장 센 숫자 예고
           7줄 안: 범위 예고 (소제목 검색어 나열) + 선택: 약속 1줄
           선택: 이탈하기 쉬운 독자에게 "○번은 꼭 보고 가세요"

[구간 ×4~6]  ### 번호. 검색어 포함 질문형 소제목
             굵은 답 1줄                     ← 구간 첫 문장 = 그 질문의 답
             시각 요소 1개 이상 (표 / ▶ 목록 / ○✕ / ☐ 체크)
             근거 문단 2~3줄 ("○○는 ~라고 안내해요" + 실천·한계 1줄. 공감 상위 글의 구간 단위)
             용어 풀이는 문장·괄호·화살표 속
             경계 문장 또는 다리 질문 1줄    ← "다만 ~", "그럼 ~는요?"

[후반]  판별 자가점검 (☐ 칸만, 앞 숫자를 다시 설명하지 않음) → 할 일 + 진정 문장
        자주 받는 질문 3~4개, 마지막 Q = 다음 질문 + 답 1줄

[마무리]  2장 마무리 풀에서 1개
          약관·상품 안내 1줄 (보험 주제일 때) ← 고정
          기준일·출처                        ← 고정
```

### 1-1. 뼈대 세부 규칙

v1.6: 위 뼈대는 **질문답변형·비교형의 기본값**이다. 아래 표의 값은 등급 0-1장 B(권고)에 해당한다. 실험형·사례형·체크리스트형은 3장의 유형별 구조를 먼저 따른다.

| 규칙 | 통과 기준 |
|---|---|
| 답 위치 | 본문 2줄째(빈 줄·사진칸 제외)에 굵은 답, `<!--결론-->` 표시 |
| 범위 예고 | 7줄 안, `<!--범위-->` 표시 |
| 소제목 | `### 숫자.`로 시작, 물음표 포함, 4~6개 + FAQ |
| 구간 첫 문장 | 굵게(`**`)로 시작 |
| 구간 시각 요소 | 모든 구간 1개 이상. 같은 내용을 표와 도식으로 두 번 넣지 않는다 |
| 이미지 리듬 | 이미지는 다음 소제목 바로 앞에 1장씩 (공감 상위 글 리듬) |
| 이탈 차단 | 판정형 표가 있으면 표 바로 아래 ✓ 한 줄 (예: "의무 없음 = 보상도 없음") |
| 클라이맥스 지연 | 글의 가장 센 숫자 구간: 굵은 답 → 자문 1줄("얼마 받았을까요?") → 표 → 결과 공개 |
| 다음 질문 | FAQ 마지막 Q에 두고 답 1줄을 반드시 준다. "다음 글은/에서는" 문장 금지 |
| 경험 | 2곳 이상, 번호·▶ 항목 속 1줄, 실제 문장만 |
| 분량 | 본문 공백 포함 1,700~2,800자 (v1.5: 구간마다 근거 문단 2~3줄을 넣으려면 2,500자로는 부족해 상향. 2,500자 상한은 v1.4에서 근거 없이 정한 값) |
| 키워드 | 본문(소제목 포함) 2~4회. 제목·태그 제외 |
| 굵은 글씨 | 구간 첫 문장과 핵심 숫자만. 문단 끝마다 굵게 하지 않는다 |

## 2. 얼굴 (매번 바꿔야 하는 부분)

의뢰인 지정 최우선 문제: **오프닝과 마무리가 매번 같은 것.**

### 2-1. 첫 줄 꼴 4가지 (직전 3편과 다른 것)

| 코드 | 꼴 | 예 |
|---|---|---|
| O1 | 검색어 + 독자 말 따옴표 | 가게 화재보험, "건물주가 들었으니 저는 괜찮죠?" |
| O2 | 검색어로 시작하는 조건 | 노쇼 위약금은 미리 알렸느냐에 따라 두 배가 갈려요. |
| O3 | 숫자 하나 | 하루 10만 원. 의무보험 만기를 넘긴 첫날부터 붙는 돈이에요. |
| O4 | 흔한 오해 반박 | 플레이스 사진은 많을수록 좋다고들 하는데, 손님은 두 장만 봐요. |

- 어느 꼴이든 **2줄째가 굵은 답**이다. 장면·계절·사연으로 3줄 이상 끄는 오프닝은 쓰지 않는다.
- 첫 줄에 **그 글에만 있는 숫자나 명사**를 1개 넣는다.

### 2-2. 마무리 꼴 5가지 (직전 3편과 다른 것)

| 코드 | 꼴 |
|---|---|
| E1 | 한 줄 원칙 ("A가 아니라 B예요") + 할 일 1개 |
| E2 | 핵심 숫자 재확인 + 할 일 1개 |
| E3 | 독자에게 되묻기 ("사장님 가게는 표의 몇 번째 칸이세요?") |
| E4 | 1인칭 한 줄 (경험 은행의 실제 문장일 때만) |
| E5 | 출구 문장 ("복잡하면 이것 하나만 하세요") |

- 마지막 문장에 **그 글에만 있는 숫자나 명사**를 넣는다.
- 마지막 문장 끝 8자가 직전 10편과 같으면 실패 (스크립트).

### 2-3. 제목 훅 (매 편, 종류는 직전 2편과 다르게)

`[메인 검색어(15자 안)] [질문]? [훅 또는 답의 범위]` · 25~40자 · 명사 5개 이상 나열 금지

| 코드 | 훅 | 예 |
|---|---|---|
| H1 | 독자 말 따옴표 | 노쇼 위약금 "예약금 받아도 돼요?" 바뀐 기준과 문자 예시 |
| H2 | 의외의 숫자 | 가게 화재보험 꼭 들어야 할까? 2천만 원 들어도 1,500만 원 나오는 이유 |
| H3 | 손실 | 재난배상책임보험 갱신 놓치면? 하루 10만 원부터 붙는 과태료 |
| H4 | 오해 반박 | 플레이스 사진 많이 올리면 좋을까? 손님이 보는 건 앞의 두 장 |

- 숫자 훅이 예시 계산이면 본문에 "예시"라고 밝힌다.

### 2-4. 용어 풀이 꼴 섞기
문장 속("구상, 그러니까 ~") / 괄호 / 화살표(→) / 표 칸 / 기울임 줄. 한 편에 2가지 이상, 기울임 줄은 한 편 2번까지.

### 2-5. 상투어 (10편에 1번 이하)
"결론부터 말하면", "핵심만 먼저", "정리해볼게요", "알아보겠습니다", "꼭 확인하세요", "도움이 되셨길", "오늘은", "많은 분들이 궁금해하시는", "다음 글은/다음 글에서는"

## 3. 글 유형

A 질문 답변형 / B 비교형 / C 사례 후기형은 **주제가 정한다** (v1.5: A→B→C 강제 순환 폐지, 토론 5명 만장일치). C형은 경험 은행에 실데이터가 있을 때만.

v1.6: 유형을 다섯 가지로 나누고, 초안 머리말 `> 글 유형:`에 적는다. 고른 이유는 초안 머리말 아래 한 줄로 남긴다. 같은 구조가 독자에게 편하면 반복해도 된다.

| 유형 (머리말 값) | 쓸 때 | 구조 | 특히 중요한 것 |
|---|---|---|---|
| 질문답변 | 구체적 질문 하나에 답과 조건을 줄 때 | 1장 뼈대 그대로 | 답의 정확성, 적용 범위 |
| 비교 | 선택지 두 개 이상의 비용·조건 비교 | 1장 뼈대 + 비교표 | 비교 기준이 공정한가 |
| 실험 | 바꾸기 전·후의 실제 결과가 있을 때 | 조건 → 바꾼 것 → 기간 → 결과 → 한계 | 바꾼 조건이 하나인가, 숫자가 실제인가 |
| 사례 | 실제 문제·조치·결과를 공개할 근거가 있을 때 | 상황 → 문제 → 조치 → 결과 → 독자에게 적용 | 경험 은행의 실제 기록, 공개 동의 |
| 체크리스트 | 독자가 자기 상황을 진단·실행해야 할 때 | 짧은 답 → 점검 칸 → 칸별 할 일 | 칸이 실제로 행동으로 이어지는가 |

경험이 없는 글은 **공식 자료로 쓰는 안내형**(질문답변·비교·체크리스트)으로 쓴다. 실험·사례는 실제 기록이 있을 때만 쓴다.

## 4. 사장님 달력

| 달 | 사장님에게 오는 일 | 글감 예시 |
|---|---|---|
| 1월 | 부가세 2기 확정신고, 설 영업 | 부가세 신고 직접 할까 맡길까? |
| 2~3월 | 봄 신메뉴, 상권 이동 | 플레이스 사진 몇 장 바꿔야 할까? |
| 4~5월 | 종합소득세, 가정의 달 | 종소세 신고 때 놓치는 경비는? |
| 6~7월 | 장마·폭염, 부가세 1기 | 장마철 누수 나면 누가 고칠까? |
| 8월 | 다음 해 최저임금 고시 | 알바 인건비 내년에 얼마나 늘까? |
| 9~10월 | 추석 영업, 가을 메뉴 | 추석 연휴 영업 안내 어떻게 올릴까? |
| 11월 | 불조심 강조의 달, 연말 단체예약 | 가게 화재보험 / 노쇼 위약금 |
| 12월 | 의무보험 갱신 점검 | 의무보험 갱신 놓치면 과태료 얼마? |

시기는 본문 첫 화면이 아니라 썸네일·태그·발행일로 쓴다 (토론 만장일치).

## 5. 형식·운영

- 한 줄 25자 안팎, 문단 2~3줄, 이미지 3~6장 (`09_image_guide.md`, v1.6: 개수는 권고. 이해를 돕는 칸만), AI 활용 표시
- 빈칸 `[숫자]`, `[경험]`이 남으면 발행 보류
- 본업 홍보·상품 권유 금지. 보험 주제는 "상품마다 약관이 다르다" 1줄
- 경험 은행: `13_experience_bank.md` (상담·방문 후 그날 1줄)
- 출처가 다르면: 법령 원문 우선 → 확인 못 하면 숫자를 빼고 "관할 기관 확인" → 확인 전 발행 보류
- 태그 10개 이하, 상업 링크 0, 발행 후 제목 수정 금지, 예전 글 재가공 금지

## 6. 초안 머리말 형식 (스크립트가 읽음)

```
> 메인 검색어: 가게 화재보험
> 글 유형: 질문답변
> 얼굴: O1 / E1 / 훅=H2
> 사실 검증: fact_checks/fire_insurance_v2.3.md
```

- 메인 검색어: 필수. 글 유형·얼굴: 권고. 사실 검증: 발행 모드에서 필수 (`fact_checks/_template.md` 형식).
- 권고에서 벗어날 때: `> 권고 예외: 분량 — 실험형이라 결과 2개만 보고` 처럼 한 줄 남긴다.

## 7. 발행 전 체크리스트 (v1.6)

1. 초안 단계: `python3 tools/check_draft.py 초안.md --prev 직전글들...` → **필수 전부 통과**. 권고는 고치거나 예외 이유를 적는다.
2. 독립 심사: 초안을 쓰지 않은 에이전트가 `19_quality_system.md` 5장 기준으로 심사.
3. 사실 검증: 검증표의 모든 줄을 '확인 완료'로 만들거나, 확인 못 한 문장을 본문에서 빼거나 범위를 좁힌다.
4. 발행 모드: `python3 tools/check_draft.py 초안.md --prev ... --publish` → 필수 전부 통과.
5. 사람 확인: 스크립트 출력의 [사람 확인] 칸을 사람이 직접 체크하고 승인.
6. 네이버에는 임시저장까지만 시스템이 하고, 발행은 사람이 "발행"이라고 한 뒤에 한다.
