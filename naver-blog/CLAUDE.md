# 네이버 블로그 자동발행 시스템 (소상공인 대상)

## 이 프로젝트가 하는 일
전주의 보험설계사(신혁)가 동네 가게 사장님(식당·카페·미용실, 40~60대 포함)의 온라인·운영 문제를 푸는 네이버 블로그를 운영한다. 승인된 지침으로 초안을 쓰고 → 기계 검사 → 독립 심사 → 사람 승인 → 발행하는 흐름을 자동화하는 것이 목표다. 본업(보험) 홍보·상품 권유는 하지 않는다.

## 문서 우선순위
1. `01_rules.md` — 벤치마킹 기반 상위 규칙 (v1.2)
2. `02_daily_guideline.md` — 일일 글쓰기 지침 (**v1.5, 2026-10-24 사용자 승인**)
3. `09_image_guide.md` — 이미지 지침 (v1.0 + v1.1 사용자 결정 추가분)
충돌하면 위가 이긴다. 지침을 바꾸면 변경 기록 표에 남긴다.

## 초안 작성 규칙 (꼭 지킬 것)
- 초안 머리말에 `> 메인 검색어:`, `> 얼굴: O? / E? / 훅=H?` 줄을 둔다. 결론 줄 끝에 `<!--결론-->`, 범위 예고 줄 끝에 `<!--범위-->`.
- 제출 전 `python3 tools/check_draft.py 초안.md --prev 직전글들...` 을 돌려 **전 항목 통과**해야 한다. 작성자 해석으로 "대체로 통과" 처리 금지 (과거 승인본에서 실제로 오판한 적 있음).
- 경험·숫자 빈칸 `[경험]`, `[숫자]`는 AI가 채우지 않는다. 지어낸 사례는 머리말에 `> 가상 시나리오: 예` 표시 → 발행 모드(`--publish`)에서 자동 실패.
- 사실(법·제도·숫자)은 공식 출처로 확인하고 기준일을 단다. 출처끼리 다르면 법령 원문 우선, 확인 전 발행 보류.
- 상업 링크 0, 태그 10개 이하, 발행 후 제목 수정 금지.
- 고품질 판정이 필요하면 **초안을 쓰지 않은 별도 에이전트**에게 심사를 맡긴다 (기준: 스크롤 유지 / 정답을 먼저 줘도 계속 읽힘 / 공감 많은 글과 구조 유사). 심사 프롬프트 예: `16_judge_v2.2.md` 상단 참고.

## 네이버 접근
브라우저(내장·크롬 확장)는 blog.naver.com을 막는다. 웹 fetch 도구로 `https://rss.blog.naver.com/<ID>.xml`(목록), `https://m.blog.naver.com/<ID>/<글번호>`(본문)를 읽는다. 방문자 수는 비공개라 확인 불가. 남의 글은 15자 이내로만 인용하고 구조만 가져온다.

## 도구
- `tools/check_draft.py` — 지침 v1.5 기계 검사
- `img/render.py` — HTML 도식을 PNG로 (Playwright, 860px 폭, 2배 해상도). 예: `img/four_way.html`

## 사용자 성향
- 결과물 위주, 수술적 수정을 선호 (통째로 다시 쓰기보다 고칠 곳만).
- 판단은 객관적 근거로, 다른 AI에게 검증받을 수 있게 근거를 남긴다.
- 지적에는 해명보다 원인과 재발 방지책을 먼저.

현재 상태와 다음 할 일은 `HANDOFF.md`.
