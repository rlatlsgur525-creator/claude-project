# 네이버 블로그 자동발행 시스템 (소상공인 대상)

## 이 프로젝트가 하는 일
전주의 보험설계사(신혁)가 동네 가게 사장님(식당·카페·미용실, 40~60대 포함)을 위한 **"사장님 돈 공부"** 네이버 블로그를 운영한다 (경제·비즈니스·보험 세 갈래, 2026-10-28부터 하루 2편 상한). 승인된 지침으로 초안을 쓰고 → 기계 검사 → 독립 심사 → 사람 승인 → 발행하는 흐름을 자동화하는 것이 목표다. 본업(보험) 홍보·상품 권유는 하지 않는다.

## 처음 읽을 순서
`CLAUDE.md`(이 파일) → `HANDOFF.md`(현재 상태·다른 컴퓨터 준비) → `19_quality_system.md`(품질 시스템 기준 문서: 작업 흐름, 사실 검증, 독립 심사 기준, 벤치마킹, 성과 학습)

## 문서 우선순위
1. `01_rules.md` — 벤치마킹 기반 상위 규칙 (v1.4, 근거 등급 [관찰]/[반복]/[가설]/[검증])
2. `02_daily_guideline.md` — 일일 글쓰기 지침 (**v1.7, 2026-10-28 사용자 지시로 개정**, v1.5 승인 기록 보존). 규칙 등급은 0-1장, 글 유형은 3장, 발행 절차는 7장
3. `09_image_guide.md` — 이미지 지침 (v1.0 + v1.1 결정 + v1.2 등급)
충돌하면 위가 이긴다. 지침을 바꾸면 변경 기록 표에 남기고, 이전 버전·승인 기록은 지우지 않는다. 규칙 하나는 한 문서에만 둔다 (어디에 있는지: `19_quality_system.md` 0장).

## 초안 작성 규칙 (꼭 지킬 것)
- 초안 머리말: `> 메인 검색어:`(필수), `> 글 유형:`(질문답변·비교·실험·사례·체크리스트), `> 얼굴: O? / E? / 훅=H?`, `> 사실 검증: fact_checks/<파일>.md`(발행 전 필수). 결론 줄 끝 `<!--결론-->`, 범위 예고 줄 끝 `<!--범위-->`.
- 검사: `python3 tools/check_draft.py 초안.md --prev 직전글들...` (Windows는 `python`). **필수 항목은 전부 통과**해야 한다. 작성자 해석으로 필수를 "대체로 통과" 처리 금지. 권고는 고치거나 `> 권고 예외:` 줄에 이유를 적는다. [사람 확인] 항목은 자동 통과가 아니다.
- 검사기를 고치면 `python3 -m unittest tools/test_check_draft.py -v`가 통과해야 한다. 기대가 바뀌면 테스트와 `19_quality_system.md` 1-4 표를 같이 고친다.
- 경험·숫자 빈칸 `[경험]`, `[숫자]`는 AI가 채우지 않는다. `13_experience_bank.md`에도 AI가 쓰지 않는다. 지어낸 사례는 `> 가상 시나리오: 예` → 발행 모드에서 자동 실패. 경험이 없으면 안내형(질문답변·비교·체크리스트)으로 쓴다.
- 사실(법·제도·숫자·약관·판결)은 `fact_checks/`에 주장별로 적고, **원문을 직접 연 것만 '확인 완료'**. 출처 충돌은 고르지 않고 보류. AI 일반 지식으로 약관·판결을 추정하지 않는다. 검증표는 발행 본문에 넣지 않는다.
- 상업 링크 0, 태그 10개 이하, 발행 후 제목 수정 금지.
- 독립 심사는 **초안을 쓰지 않은 별도 에이전트**에게 `19_quality_system.md` 5장 기준(10항목, 유형별 비중, 하나의 점수로 합치지 않음)으로 맡긴다. AI 심사 통과를 실제 독자 검증으로 보고하지 않는다.
- 네이버에는 Uplika로 **임시저장(draftOnly)까지만** 한다. 발행은 사용자가 "발행"이라고 한 뒤. 임시저장 글을 고칠 때 `update_post`를 쓰면 바로 발행되므로, 새로 임시저장하고 구판은 사용자 확인 후 삭제한다.

## 네이버 접근
브라우저(내장·크롬 확장)는 blog.naver.com을 막는다. 웹 fetch 도구로 `https://rss.blog.naver.com/<ID>.xml`(목록), `https://m.blog.naver.com/<ID>/<글번호>`(본문)를 읽는다. 방문자 수는 비공개라 확인 불가. 남의 글은 15자 이내로만 인용하고 구조만 가져온다.

## 도구
- `tools/check_draft.py` — 지침 v1.6 기계 검사 (필수/권고/정보/사람 확인, 필수 실패만 종료 코드 1)
- `tools/test_check_draft.py` — 검사기 회귀 테스트 (외부 패키지 없음)
- `tools/news_fetch.py` — 비즈니스 갈래 새 소식 수집 (네이버 뉴스 검색 API, 키는 `.env`에 사용자가 직접). 검색어는 `tools/news_queries.txt`
- 주제 탐색: `.claude/skills/topic-scout` ("주제탐색"), 기준·기록은 `20_topic_scout.md`
- `img/render.py` — HTML 도식을 PNG로 (Playwright, 860px 폭, 2배 해상도). 예: `img/four_way.html`. Playwright가 없으면 Edge headless (HANDOFF "도구")

## 사용자 성향
- 결과물 위주, 수술적 수정을 선호 (통째로 다시 쓰기보다 고칠 곳만).
- 판단은 객관적 근거로, 다른 AI에게 검증받을 수 있게 근거를 남긴다.
- 지적에는 해명보다 원인과 재발 방지책을 먼저.

현재 상태와 다음 할 일은 `HANDOFF.md`.
