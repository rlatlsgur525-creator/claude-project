# 이미지 지침 v1.0

상위: `01_rules.md` 6장(유사 이미지 = 저품질 신호), `02_daily_guideline.md`
원칙: **가져올 수 있는 건 라이선스가 확인된 것만 가져오고, 한눈에 봐야 이해되는 것만 만든다.**

---

## 1. 먼저 바로잡을 것: "출처만 밝히면 된다"는 틀렸다

- 남이 찍은 사진은 출처를 밝혀도 **허락이 없으면 저작권 침해**다. 출처 표시는 허락을 대신하지 않는다.
- 다른 블로그·뉴스·업체 사진은 이미 다른 글에 쓰인 이미지라 **유사 이미지(저품질) 신호**도 된다.
- 그래서 "기존 이미지"는 **이용 허락이 미리 붙어 있는 이미지**(공공누리, 무료 스톡)로만 한정한다.

| 출처 | 쓸 수 있나 | 조건 |
|---|---|---|
| 다른 블로그·뉴스·카페 사진 | 불가 | 출처를 밝혀도 불가 |
| 보험사·업체 홍보 이미지 | 불가 | 광고 이미지 + 저작권 |
| 네이버·구글 이미지 검색 결과 | 불가 | 라이선스 불명 |
| 공공누리 제1유형 | 가능 | 출처 표시. 상업적 이용·변경 가능 |
| 공공누리 제3유형 | 가능 | 출처 표시. 변경 금지 (자르기·글씨 얹기 불가) |
| 공공누리 제2·4유형 | 피함 | 영리 목적 이용 금지 (블로그가 상담으로 이어지므로 안전하게 제외) |
| Unsplash, Pixabay | 가능 | 무료·상업 이용 가능, 출처 표시 의무 없음(권장). 상표·로고가 보이는 사진은 제외 |
| 직접 촬영·직접 캡처 | 가능 | 사람 얼굴·차량번호·개인정보 가림, 가게는 사장님 동의 |

## 2. 이미지 유형 5가지와 우선순위

| 순위 | 유형 | 언제 쓰나 | 누가 만드나 |
|---|---|---|---|
| 1 | **직접 촬영·캡처** | 실제 가게, 실제 조회 화면, 실제 서류 | 사람 (시스템은 촬영 목록만 만듦) |
| 2 | **공공누리 자료** | 공식 안내 그림, 통계 그림을 그대로 보여줄 가치가 있을 때 | 시스템이 후보 링크 + 유형 확인 |
| 3 | **무료 스톡** | 분위기·장면 사진 (썸네일, 문단 전환) | 시스템이 검색어 제시, 사람이 고름 |
| 4 | **직접 렌더 도식** | 숫자 비교, 판정 흐름, 구조, 계산 예시 | 시스템이 데이터로 그림 (HTML→PNG) |
| 5 | **AI 생성 일러스트** | 사진이 존재할 수 없는 장면·개념 (글자 없이) | 시스템이 프롬프트 작성 → 생성 |

### 2-1. 도식은 AI 이미지로 만들지 않는다

표·흐름도·계산처럼 **글자와 숫자가 정확해야 하는 그림**은 AI 이미지 생성기를 쓰지 않는다. 한글이 깨지고 숫자가 틀어진다. 데이터로 HTML을 그려 PNG로 저장한다 (기존 Playwright 렌더 파이프라인 재사용).

### 2-2. AI 생성은 "글자 없는 장면"만

AI 이미지는 글자·숫자·로고 없이 장면만 만든다. 설명 글자가 필요하면 생성된 그림 위에 도식처럼 HTML로 얹는다.

## 3. 어떤 칸에 어떤 유형을 쓸지 (판단 순서)

초안의 `[사진: …]` 칸마다 시스템이 아래 순서로 묻고 첫 번째 "예"에서 멈춘다.

1. 실제 화면·서류·가게를 보여줘야 하나? → **직접 촬영·캡처**
2. 숫자, 비교, 판정 조건, 흐름, 구조를 한눈에 보여줘야 하나? → **직접 렌더 도식**
3. 공식 기관 그림을 그대로 보여주는 게 가장 정확한가? → **공공누리 (1·3유형만)**
4. 분위기·장면이면 충분한가? → **무료 스톡**
5. 위가 다 안 되는데 장면이 꼭 필요한가? → **AI 생성 (글자 없음)**
6. 다 아니면 → 그 칸을 지운다. 이미지 개수를 채우려고 넣지 않는다.

본문에 이미 표로 있는 내용을 같은 모양의 이미지로 또 넣지 않는다. 이미지는 표가 못 보여주는 것(흐름, 방향, 크기 차이)을 맡는다.

## 4. 한 편당 구성 기준

| 항목 | 기준 |
|---|---|
| 총 개수 | 3~6장 |
| 직접 촬영·캡처 | 최소 1장 (경험의 증거, 신념 6) |
| 직접 렌더 도식 | 1~2장 |
| 무료 스톡 | 2장 이하, 반드시 변형 (자르기·색 보정·글씨 얹기) |
| AI 생성 | 1장 이하 |
| 재사용 | 금지. 썸네일 틀이 같아도 배치·색·문구는 매번 다르게 |

## 5. 시스템 출력 형식 (이미지 칸마다)

```
- 칸: [사진 1] 결론 표 아래
  목적: 우리 가게가 의무 대상인지 확인하는 화면
  유형: 직접 캡처
  담당: 사람
  찍을 것: 생활안전지도 > 의무보험 조회 > 상호명 검색 결과 (상호명 가림)
  대체텍스트: 생활안전지도에서 상호명으로 재난배상책임보험 대상 여부를 조회한 화면
  캡션: 생활안전지도 조회 화면 (직접 캡처)
```

유형별로 추가로 채우는 칸:

| 유형 | 추가 항목 |
|---|---|
| 공공누리 | 원본 링크, 공공누리 유형 번호, 출처 표기 문구 |
| 무료 스톡 | 검색어(영문), 고르는 기준, 변형 지시, 사진가 이름 |
| 렌더 도식 | 템플릿 이름, 들어갈 데이터, 크기 |
| AI 생성 | 프롬프트, 금지어, 크기 |

## 6. 템플릿과 프롬프트

### 6-1. 렌더 도식 템플릿 (HTML→PNG)

| 템플릿 | 쓰임 | 데이터 형식 |
|---|---|---|
| `flow` | 판정 흐름 (예/아니오 갈림) | 질문 노드, 예/아니오 연결, 결과 |
| `bar-compare` | 금액·시간 비교 막대 | 항목명, 값, 단위, 강조할 항목 |
| `four-way` | 한 사건에서 갈라지는 4방향 | 가운데 사건, 4개 대상, 각 대상의 해결책 |
| `before-after` | 전후 비교 | 항목, 전 값, 후 값 |
| `checklist-card` | 오늘 할 일 카드 | 항목 3~5개 |
| `thumbnail` | 썸네일 (스톡 사진 + 제목 글씨) | 배경 사진 경로, 제목 2줄, 강조 단어 |

공통: 가로 860px(네이버 본문 폭 기준) × 세로 자유, 한글 폰트 Pretendard, 글자 최소 28px(모바일 판독), 색은 블로그 브랜드 색 3개 이내. 같은 템플릿이라도 편마다 배치·강조색을 돌린다.

### 6-2. AI 프롬프트 작성 규칙 (v1.1, 2026-10-24 개정)

v1.0 프롬프트로 A안 썸네일을 돌렸더니 금지 4개(화면 글자, 간판 글자, 손·얼굴, 실제 가게처럼 보임)가 **전부** 나왔다. 원인은 금지할 물건을 프롬프트에 직접 적은 것이다. "screen", "sign", "hands", "Korean restaurant"를 쓰면 모델은 그걸 그린다.

근거 (공식 가이드):
- Google Gemini 이미지 생성 가이드: "no cars" 대신 "an empty, deserted street"처럼 **원하는 장면을 긍정형으로 묘사**(semantic negative prompt), 카메라 용어로 구도 통제, 후속 프롬프트로 작게 고치기
- OpenAI 이미지 프롬프트 가이드: 장면 → 주인공 → 세부 → 제약 순서, 용도 명시, 한 번에 한 가지만 고치며 반복

| # | 규칙 | 나쁜 예 | 좋은 예 |
|---|---|---|---|
| 1 | 금지 대상은 **이름을 부르지 말고**, 그게 생길 자리 자체를 없앤다 | a smartphone with no visible screen content | a smartphone lying face down |
| 2 | 글자가 생길 물건(간판·메뉴판·포스터·포장지·화면)을 **화면에 넣지 않는다** | restaurant interior, no signs | close-up of a bare wooden counter against a plain cream wall |
| 3 | 배경은 **좁게 자르거나 흐리게** (macro, tight crop, out-of-focus background) | wide shot of the dining room | macro shot, background dissolved into soft warm blur |
| 4 | 나라·업종 이름을 빼고 **물건·재질로** 묘사 | Korean restaurant | stainless steel rice bowls, worn wooden counter |
| 5 | 사람은 "없다"고 쓰지 말고 **사람이 들어갈 이유가 없는 구도**로 | no people, no hands | still life of objects on a counter |
| 6 | 사례 글은 **사진풍 금지, 일러스트풍** (실제 가게·증빙으로 오해 방지) | realistic photo | soft paper-cut illustration / flat illustration |
| 7 | 마지막에 용도·비율 한 줄 | (없음) | Blog thumbnail, 4:3, generous empty space on the left for a title added later |

**금지 대상 (AI로 절대 만들지 않음):** 리뷰·앱·웹 화면, 영수증·증권·계약서, 실존 가게·간판, 사례 속 가게·음식·사람을 닮은 그림, 실존 인물

**고치기 (한 번에 하나씩, 후속 프롬프트로):**
- 글자가 생겼을 때: "Keep everything the same, but make the [위치] a plain blank surface."
- 사람이 끼었을 때: "Keep everything the same, but remove the person and leave the space empty."
- 실제 가게 같을 때: "Keep the composition, but change the style to a soft paper-cut illustration."
- 3번 고쳐도 안 되면 그 칸은 렌더 도식이나 직접 촬영으로 바꾼다.

**프롬프트 카드 형식 (시스템 출력):** 칸 / 한 줄 설명 / 영어 프롬프트 / 비율 / 돌린 뒤 체크 4개 / 실패 시 고치기 문장

- 화재·사고 장면은 겁주는 연출(불길에 휩싸인 사람 등)을 쓰지 않는다. 연기·소화기·빈 가게처럼 상황만 보여준다.

### 6-3. 무료 스톡 검색어 틀

- 영문 2~4단어: `restaurant kitchen fire extinguisher`, `small cafe closed night`
- 고르는 기준: 상표·간판 글씨 안 보임, 사람 얼굴 정면 아님, 한국 가게와 어울림
- 변형: 4:3 또는 1:1로 자르기 + 색 보정 + (썸네일이면) 제목 글씨 얹기

## 7. 발행 전 이미지 체크

- [ ] 모든 이미지의 유형·출처·라이선스가 기록됨
- [ ] 다른 블로그·뉴스·업체·검색 이미지 0장
- [ ] 공공누리는 1·3유형만, 출처 표기 문구 있음
- [ ] 직접 촬영·캡처 1장 이상
- [ ] 도식에 글자·숫자가 정확함 (본문 숫자와 대조)
- [ ] AI 이미지에 글자·로고 없음
- [ ] 이전 글과 같은 이미지 없음
- [ ] 개인정보(얼굴, 상호, 번호) 가림 또는 동의

## v1.1 추가 (2026-10-24, 사용자 결정)

1. **화면·기록은 무조건 실물 캡처.** 네이버 리뷰 화면, 스마트플레이스 메뉴, 보험증권, 계약서, 영수증처럼 사실을 증명하는 이미지는 AI로 만들지 않는다. 실제 가게 화면을 사장님 동의를 받아 캡처하고, 리뷰 작성자 닉네임·프로필은 가린다. 악성 리뷰 원문은 흐리게 처리하고 답글·신고 화면 위주로 쓴다.
2. **AI 이미지는 실사 흉내를 내지 않는다.** 대놓고 그림으로 보이는 화풍(카툰·일러스트 등)만 쓰고, 그림 아래에 "AI로 그린 그림" 캡션을 단다. 실사풍 프롬프트(cinematic, realistic photo 등)는 쓰지 않는다.
3. **사례 글에서 AI 그림은 사례 속 가게·음식·사람을 닮으면 안 된다.** 증빙처럼 읽히는 그림 금지.
4. **생성은 사용자가 ChatGPT·Gemini에서 직접 한다.** 시스템은 칸마다 프롬프트 카드(영어 프롬프트, 한 줄 설명, 금지 목록, 비율, 오해 소지 체크)를 만든다. 한글 제목은 이미지에 넣지 않고 렌더(`img/render.py`)로 얹는다.
5. **고정 화풍·캐릭터는 검토 중.** 후보 화풍 5가지(①플랫 벡터 ②한국 웹툰 ③흑백 잉크 펜화 ④수채화 ⑤클레이 미니어처) 비교 이미지를 사용자가 생성해 고르는 단계. 고정 캐릭터 도입도 검토 중(추천: 신혁 님을 닮은 캐릭터, 또는 실루엣만 닮게). 정해지면 캐릭터 시트를 한 번 만들고 매번 참조 이미지로 함께 올린다. 회사 로고·색 금지.
