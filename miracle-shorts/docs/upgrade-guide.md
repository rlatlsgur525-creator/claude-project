# 미라클 쇼츠 고도화 지침서 (사용자 제공, 2026-10-25)

AI 기반 스토리보드·키프레임·장면 편집 시스템 구축. 원문 요약 — 작업 시 이 순서를 따른다.

## 목표
템플릿 기반 생성기 → AI가 영상 구조를 설계하고, 사람이 장면별로 검수·수정한 뒤 최종 영상을 만드는 편집 시스템.
장면 하나를 바꿔도 전체를 처음부터 다시 만들지 않는다. 참고: 쇼츠 에디터 시연(대본·오디오 → 장면 분할 → 키프레임·스토리보드 → 영상 생성 → 헤드라인·자막 → 출력), https://prinsketch.shop/editor (내부 코드 없음 — 흐름만 참고).

## 원칙
1. 기존 코드를 먼저 분석 2. 렌더 엔진·편집 기능 불필요한 재작성 금지 3. 작은 단위로 순차 구현 4. AI는 검증된 구조·작업 명세로만 수정
5. 장면 계획·키프레임·영상 파일·타임라인 구간을 구분 6. 미구현을 구현됐다고 보고하지 않음 7. 비밀 정보 하드코딩 금지
8. 템플릿 작업 하위 호환 9. AI 이미지·영상 API 연결은 데이터 구조·편집 기능 안정화 후 10. 태블릿에서 가로 스크롤 금지
충돌 발견 시 크게 바꾸지 말고 충돌 지점과 대안을 먼저 확인.

## 데이터 모델 (논리 구분)
Project(ID·제목·비율·FPS·버전·대본/음성·장면·타임라인·렌더/검수 상태) · Shot(ID·목적·설명·대사·예상 길이·시각 자료 유형·프롬프트·키프레임·소스·자막/모션) ·
Keyframe(ID·장면ID·에셋·프롬프트·참조·생성/승인 상태·역할/순서) · Asset(ID·경로·유형·출처·상태·메타) ·
Segment(타임라인의 실제 재생 구간·소스·in/out·길이·속도/크롭/줌·장면ID) · TimelineItem(클립·자막·그래픽·음성·효과음·BGM, 시간·트랙·속성).
키프레임 ≠ 세그먼트. 개수 고정 규칙 없음.

## 단계
- Phase 0 기존 코드 감사 → `docs/phase0-audit.md`
- Phase 1 공통 장면 데이터 모델(변환·스키마 버전·검증·기존 프로젝트 정상 동작)
- Phase 2 스토리보드·장면별 편집(카드, 선택·수정, 소스 교체, 길이, 순서, 추가·삭제, 장면 미리보기)
- Phase 3 장면별 캐시·재렌더(장면 해시, 미변경 재사용, 무효화 검증)
- Phase 4 AI 장면 계획(구조화 출력 + 스키마 검증 → 스토리보드 → 검수 후 렌더). 제공업체는 별도 연동 계층
- Phase 5 키프레임·외부 생성기(이미지·참조·상태·선택적 영상·재시도·기존 결과 보존)
- Phase 6 문장 단위 대본·음성 정렬, 성과 측정
