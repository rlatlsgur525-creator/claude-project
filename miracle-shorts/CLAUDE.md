# 미라클 쇼츠 프로젝트 — 인수인계 (최종 갱신 2026-10-25)

이 폴더는 김신혁(신혁)의 유튜브 쇼츠 프로젝트다. 이 문서를 먼저 읽고, 이어서 **`docs/STATUS.md`(진행 상황·다음 할 일)**를 읽은 뒤 작업한다.

## 이어서 작업할 때 (먼저 읽기)

1. `git pull` → `docs/STATUS.md` → `docs/upgrade-guide.md`(사용자의 고도화 지침서 요약) → `docs/phase0-audit.md`
2. 지금 진행 중인 큰 흐름: **고도화 지침서 Phase 1~2 완료 → 다음은 실제 사용성 평가 후 Phase 4(AI 장면 계획)**. 지침서 원칙: 작은 단위로, 기존 렌더 엔진 재작성 금지, 미구현을 구현됐다고 말하지 않기, 태블릿 가로 스크롤 금지.
3. 검증: `cd studio && python tests/test_scenes.py` (최종 MP4까지: `--final`). 32개 검사.
4. 실행: 바탕화면 "미라클 쇼츠 스튜디오" 또는 `studio/start.bat` → http://127.0.0.1:8765
5. 새 컴퓨터: Python 3.12 + `pip install numpy pillow` + ffmpeg(`winget install Gyan.FFmpeg`). 마스코트 동작 클립(`studio/library/anim/*.mp4`)은 저장소에 들어 있다.

## 지금까지 정한 방향 (시간순)

1. **AI "딸깍" 영상 분석:** 사용자가 보여준 앱 홍보 쇼츠("심기좋게")는 영상 생성 AI가 아니었다. AI로 만든 캐릭터 이미지와 코드 모션그래픽(HTML/CSS·Remotion류)을 합친 영상이었다.
2. **쇼츠 기획 툴은 폐기:** 처음에 포맷 선택형 "쇼츠 기획실" 아티팩트를 만들었으나 "주제가 너무 정해진 느낌"이라 삭제했다. → **프리셋 없이, 소재에서 출발하는 방식**으로 전환했다.
3. **공개 스킬 참고:** appie-kit(viral-shorts-course, video-editing-pro, video-use, MIT), HyperFrames, Remotion 스킬을 참고해 두 개의 스킬을 만들었다(아래 `skills/`).
4. **포맷 우선 전략 (사용자 핵심 철학):** "내 주제에서 잘 된 영상 찾기"가 아니다. **주제와 무관하게 작은 채널에서 크게 터진 포맷**(예: 1만 채널에서 100만)을 먼저 찾고, 그 다음에 내 주제를 이식할 수 있는지 판정한다.
5. **첫 아웃라이어 스캔 완료:** 결과는 `hunter/results/`에 있다. 상위 포맷은 다음과 같다.
   - 경고형 "절대 ~하지 마세요" (이식 40점)
   - 현장 반전 썰 (38점)
   - 거인 대결·반전 (32점)
   - 작은 권력 빌런 썰 (31점)
   - 비교 실험 (29점)
6. **채널 메인 기획 = "약관 전수조사":** 건강보험 담보별(예: 수술비)로 전 생보·손보사 약관을 비교한다. 회사는 익명으로 처리하고 "넓게 보장 / 표준 / 확인 필요" 3그룹으로 나눈다. 쇼츠는 경고형 훅 + 전수조사 등급표 + 반전 구조로 만든다. **확인 방법(셀프체크)은 영상 안에서 반드시 알려준다.** 답을 숨기면 분노 댓글이 생겨 신뢰가 무너진다(스캔 사례에서 확인됨). 상세 표는 리포트 페이지로 보낸다.
7. **리포트 페이지 제작:** claude.ai 아티팩트로 만들었다(`report/`). 현재 내용은 **예시 데이터**이고, 실제 약관 데이터를 넣는 것이 다음 할 일이다.

## 스튜디오 (2026-10-24, 첫 버전)

- **실행:** 바탕화면 "미라클 쇼츠 스튜디오" 아이콘(= `studio/start.bat`) → 브라우저에 http://127.0.0.1:8765 . 창을 닫으면 꺼진다.
- **흐름:** 프로젝트 고르기 → 칸 고치기(자동 저장) → [미리보기] 약 15초 → [최종 만들기] → `studio/projects/<이름>/final.mp4`
- **화면 (v2, 영상 편집기형):** 오른쪽 영상은 항상 보임(좁은 화면에선 위에 고정). 아래 타임라인 트랙: 장면 / 자막(끌어서 이동·양 끝으로 길이) / 준법 표기 / 효과음(높이 = 크기, 끌어서 이동, + 추가) / 배경음악(크기·덕킹) / 실제 음량 파형(렌더 결과 dB). 항목을 누르면 왼쪽 '선택한 항목'에서 문구·시간·소리·크기를 고친다. "고치면 자동 미리보기"가 켜져 있으면 2초 뒤 자동 렌더.
- **타임라인 수정값 저장:** `data.json`의 `tl.cap_times`, `tl.sfx`, `bgm` (↺ 버튼 = 템플릿 기본값으로). 렌더 상태는 `render.json`(데이터 해시)로 "영상 최신 / 고친 내용 미반영"을 판단.
- **배경음악:** `studio/music/` 폴더에 음원을 넣고 고른다(저장소에 올리지 않음). 저작권 걱정 없는 음원만.
- **템플릿 3개** (`studio/templates/`): `terms_survey` 약관 전수조사(30초), `warning` 경고형(25초, B 설계도), `experiment` 비교 실험(30초, E 설계도·숫자는 코드 계산)
- **템플릿 규약:** `NAME, DESC, FIELDS, validate(data), build(data) -> (scenes, captions, sfx, note)`. 새 템플릿은 `pipeline.TEMPLATES`에 키를 추가한다. 그리기 공통 도구는 `studio/gfx.py`.
- **자동 준법:** 심의필 번호가 비면 화면에 "심의 전 · 게시 불가", 예시 데이터 표기, 단정 표현·긴 자막·60초 초과 경고. 목록에 심의 상태(심의 전/완료/만료) 표시.
- **Claude가 초안을 만들 때:** `studio/projects/<이름>/data.json`을 템플릿 기본값 + 주제 내용으로 채워 저장하면, 사용자가 툴에서 열어 고친다.
- **v3 (프리미어식 편집, 2026-10-24):** 0.01초·1프레임 단위 시간(시간 칸에 1.17 입력, ←→ 1프레임), 끼워넣기(리플 삽입: 빈 화면·이미지·영상, 뒤가 밀림), I/O 구간 삭제(뒤가 당겨짐, 되살리기 가능), 자르기(S), 직접 글자(모양·색·위치·크기), 이미지·영상 얹기(V2, 화면에서 노란 상자로 위치·크기), 내 목소리 녹음(재생 위치부터), 마커, 되돌리기/다시하기, 자석(스냅), 타임라인 확대, 구간 반복, 미디어 탭(올리기·공용 라이브러리), 업로드 탭(제목·설명·해시태그·SRT·썸네일). 단축키는 툴의 '단축키' 탭.
- **시간 규칙 (중요):** 템플릿 자막·효과음은 원래 시간 → `edits`를 거쳐 최종 시간으로 옮긴다. 사용자가 넣은 것(`texts`, `overlays`, `voices`, `markers`, `tl.*`)은 최종 시간으로 저장하고, 끼워넣기·구간 삭제 때 화면(UI)이 함께 민다. 자세한 키 설명은 `studio/pipeline.py` 맨 위.
- **장면 캐시:** 장면 그림에 영향 없는 수정(자막·효과음·글자·얹기 등)은 장면 클립을 재사용해 미리보기가 약 7초.
- **공용 라이브러리:** `studio/library/` (마스코트 포즈 등, 모든 프로젝트의 미디어 탭 [공용]). 프로젝트 전용 파일은 `projects/<이름>/media/`.
- **마스코트:** `brand/mascot/README.md` (설정·포즈·새 포즈 만드는 법, Higgsfield 요소 `miracle-fp`).
- **다음 기능 후보:** C 루프형 템플릿, 얼굴 출연(A·D)용 촬영본 템플릿(촬영본 자르기·말 구간 자동 컷), 내레이션 자동 자막(음성 인식), 키프레임 이동(확대·이동 애니메이션)

## 로컬(이 PC)에서 이어갈 때

- **필요 프로그램:** Python 3, `pip install numpy`, ffmpeg(PATH에 등록, libass 포함 빌드). 윈도우는 `winget install Gyan.FFmpeg` 등으로 설치.
- **build.py의 경로 규칙:** fonts·sfx 폴더는 build.py와 같은 폴더를 기본으로 쓴다. edl.json에서 `fonts`/`sfx_dir`를 생략하면 된다.
- **유튜브 API:** 클라우드 세션에서는 googleapis.com이 막혀 있어서 우회 조회로 소규모 스캔만 했다. **로컬에서는 바로 된다.**
  - 키는 파일에 저장하지 말고 환경변수로만 쓴다: PowerShell `$env:YT_KEY="..."` 후 `python hunter/scan.py --out hunt_MMDD`
  - 사용자에게 키를 다시 받는다
  - 키가 채팅에 한 번 노출됐으므로, 구글 클라우드에서 'YouTube Data API v3 전용'으로 제한돼 있는지 확인을 권한다
- **스킬 설치:** `skills/` 아래 두 폴더를 `~/.claude/skills/`에 복사하면 Claude Code 스킬로 쓸 수 있다. SKILL.md의 '0. 준비' 단계는 클라우드용(`~/shorts-kit` 경로, npm으로 폰트 받기)이므로 로컬에서는 이 폴더의 `shorts-kit/`을 그대로 쓰도록 경로만 바꾸면 된다.

## 반드시 지킬 것 (준법)

- **보험업법 제97조:** 비교 대상과 기준을 분명히 밝혀야 한다. 객관적 근거 없이 다른 상품이 우수하거나 유리하다고 알리면 안 된다. → 조항명, 문구, 기준월, 상품 범위를 항상 표기한다. 불리한 쪽 원문은 회사가 특정되지 않게 요약한다.
- **사전 심의:** 설계사 유튜브와 리포트는 회사 준법감시 사전 심의와 '심의필' 표기 대상이 될 수 있다(금감원이 2025년부터 점검 중). 시리즈 시작 전에 포맷을 준법감시인과 협의하도록 권했다.
- **미라클톡 쇼츠 공통 규칙:**
  - 수익률 보장·"무조건" 같은 단정 표현 금지
  - 특정 상품명·회사명 홍보 금지
  - 숫자 예시는 "연 ○% 가정·세전·수수료 미반영"을 화면에 표기
  - 숫자는 코드로 계산해서 검증한다
- **이해 상충:** 사용자는 메트라이프(생보) 소속이다. 전속인지 GA인지는 아직 답을 받지 못했다. 비교 콘텐츠의 공정성과 상담 연결 구조를 설계할 때 꼭 확인한다.

3. **로컬에서 scan.py 실제 실행:** 검색어와 카테고리를 넓혀 포맷 라이브러리를 늘린다.
4. **쇼츠 링크 문제 확인:** 쇼츠 댓글·설명란 링크는 클릭이 안 될 수 있다(2023년 변경으로 알고 있으나 확인 필요). 대안은 프로필 링크, 관련 동영상 연결, 카카오톡 채널 키워드 자동응답이다(마지막 것을 추천했다).

### 수술비 편 쇼츠 구조 (합의안)

| 시간 | 화면 | 자막 / 말 |
|---|---|---|
| 0~2초 | 익명 카드 24장, 그중 2장만 빨강 | "수술비 싸서 가입했다면 / 이 [2곳]인지 확인하세요" |
| 2~5초 | 약관 PDF가 쌓이는 화면 | "24개 보험사 수술비 약관, 전부 비교했습니다" |
| 5~12초 | 카드가 18 / 4 / 2로 정렬 | "18곳은 거의 같고, [4곳]은 더 넓게 줍니다" |
| 12~20초 | 초록 카드 뒤집기 | "'수술'에서 빼는 항목이 더 적어요" |
| 20~26초 | 잠깐 멈춘 뒤 빨간 카드 뒤집기 | "이 2곳은… [티눈·사마귀]를 수술로 안 봅니다" (예시. 실제 데이터로 교체) |
| 26~30초 | 약관 '수술의 정의' 조항 짚기 | "내 약관에 이 문구가 있는지만 보세요" → 바로 끝 |

시리즈 이름은 "약관 전수조사 #1 수술비, #2 입원일당…" 식으로 번호를 붙인다. 매달 약관 개정 업데이트 편도 만든다. 가끔 얼굴 출연 현장 썰(A 포맷)을 섞어 신뢰를 쌓는다.
